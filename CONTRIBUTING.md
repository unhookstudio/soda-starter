# Contributing

Issues and focused pull requests are welcome, but review is best-effort and the
project has no support SLA.

Before proposing a change:

1. explain the concrete starter-wide problem rather than one product's custom
   requirement;
2. keep authorization, transactions, side effects, tests, OpenAPI, and
   documentation consistent;
3. run the verification commands in the README;
4. avoid unrelated formatting, dependency, or architecture changes.

Security vulnerabilities must follow [SECURITY.md](SECURITY.md), not the public
issue tracker.
